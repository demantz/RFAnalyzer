# librtl433 native module

This module compiles [rtl_433](https://github.com/merbanan/rtl_433) as a shared
library and exposes a small "push" API so RF Analyzer can decode the IQ stream
it already receives. It does **not** let rtl_433 open an SDR.

## Layout

| File | Purpose |
|---|---|
| `rfax_bridge.h` / `rfax_bridge.c` | Format-agnostic decoder API (no Android/JNI types, host-testable) |
| `rfax_channel.h` / `rfax_channel.c` | Optional channel filter (mix + low-pass before decimation) |
| `rfax_jni.cpp` | JNI glue used by `Rtl433Native.kt` |
| `rfax_feed_hook.inc` | Additive hook appended to a generated copy of `rtl_433.c` |
| `rtl_433/` | rtl_433 submodule, pinned to tag `25.12` |
| `CMakeLists.txt` | Builds all of the above |

## Getting the source

rtl_433 is a submodule. After cloning the project:

```
git submodule update --init --recursive
```

The submodule is pinned to release `25.12`
(`ea7d504877df751a202432d47dbb0c425ab0a93c`).

## Why a generated copy of `rtl_433.c`

rtl_433's sample-processing entry point, `sdr_callback()`, is `static`. The
cleanest way to feed samples without duplicating that logic is a one-function
hook (see `rfax_feed_hook.inc`). Instead of patching the submodule at build time
(which would leave the working tree dirty and surprise reviewers), CMake reads
`src/rtl_433.c`, appends the hook, and compiles the result as
`rtl_433_embedded.c`. Every other rtl_433 file is compiled unmodified.

## Divergence from upstream

The submodule is **not modified**. All adaptation lives in this directory:

| Divergence | Where | Purpose |
|---|---|---|
| `rfax_sdr_feed()` appended to a generated copy of `rtl_433.c` | `rfax_feed_hook.inc` + `CMakeLists.txt` | calls the static `sdr_callback()` so the app can push IQ samples |
| `pthread_cancel` → `rfax_pthread_cancel` for `output_rtltcp.c` | `rfax_bionic_compat.*` + `CMakeLists.txt` | Bionic has no thread cancellation; the (unused) rtl_tcp output sink needs it to link |

Nothing else is changed. If either assumption breaks, the build fails loudly
(CMake `FATAL_ERROR` / link error), which is the intended signal.

## Updating rtl_433

```
cd librtl433/src/main/cpp/rtl_433
git fetch --tags
git checkout <new-release-tag>
cd -
git add librtl433/src/main/cpp/rtl_433   # record the new commit
```

Then:

1. Rebuild. If `rtl_433.c` still defines `static void sdr_callback(unsigned
   char *, uint32_t, void *)`, the hook (which is just appended text) keeps
   working unchanged. If its signature or name changes, update
   `rfax_feed_hook.inc` accordingly.
2. If new core sources call Bionic-incompatible functions, extend
   `rfax_bionic_compat.*`.
3. Re-run the host test described below (ideally with a capture whose expected
   JSON was generated by the new rtl_433 release) and a device smoke test.

The decoder public API used by the bridge (`r_create_cfg`, `r_init_cfg`,
`r_free_cfg`, `register_all_protocols`, `pulse_detect_set_levels`,
`data_print_jsons`, `struct dm_state` fields) has been stable across recent
releases. Keep the submodule pin at a tagged release so upgrades are explicit.

## Sample format

`rfax_rtl433_feed()` takes interleaved, normalised complex samples
`[i0, q0, i1, q1, ...]` in roughly `[-1, 1]`. This is exactly the buffer RF
Analyzer builds for the FFT, so no per-source format handling is needed. The
bridge converts to CU8 (rtl_433's native format) and optionally decimates by an
integer factor before decoding.

## Host testing

The bridge has no Android dependencies and can be built against a rtl_433
checkout to run the decoder on recorded samples:

```
gcc -O2 -I rtl_433/include -I rtl_433/src -I rtl_433/src/devices -I . \
    -c rfax_bridge.c -o rfax_bridge.o
# ... link with the rtl_433 core and device objects, plus a small test main.
```

A single CU8 sample can be fed as normalised floats; decoded events are
delivered through the callback as JSON.
